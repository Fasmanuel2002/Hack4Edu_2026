Architecture

How Twins for Change works

Gemma 3 4B makes things up when it answers in Yorùbá. Twins for Change retrieves verified bilingual examples with hybrid RAG and gives them to Gemma, so it answers from real data. The demo compares plain Gemma with Gemma + RAG on the same question.

From question to bilingual answer

  1. Question

    In Yorùbá or English. Each request carries one question and no chat history.

  2. Hybrid search

    bge-m3 + BM25 over the 15,791-row corpus, fused with RRF. Top 3 results.

  3. Tutor prompt

    The question plus the 3 retrieved pedagogical_answer texts.

  4. gemma3:4b

    Generates through Ollama with temperature 0.1.

  5. Bilingual answer

    Main explanation in Yorùbá, key terms and a summary in English, step by step.

The baseline in compare mode

  1. Question
  2. gemma3:4b, no retrieved context
  3. Plain answer

POST /ask/plain sends the same question to Gemma with no context. In compare mode the chat sends both requests at once and shows the answers side by side.

Pipeline settings

Vector database
Qdrant collection hack4edu_collection in hybrid mode
Dense vectors
bge-m3 through Ollama: 1024 dimensions, cosine distance
Sparse vectors
Qdrant/bm25 through FastEmbed, with the IDF modifier
Fusion
Reciprocal Rank Fusion (RRF) combines the two result lists
Results
Top 3 documents. k=3 is the number of results, not an RRF parameter.
Search matches
search_context: the question, written as Yorùbá | English
Gemma reads
pedagogical_answer: the verified content and answer
Generation
gemma3:4b through Ollama, temperature=0.1, num_ctx=8192
Tutor prompt
Main explanation in Yorùbá, key terms and a summary in English, step-by-step reasoning. When nothing relevant was retrieved, Gemma is asked to say that the topic is not in the database yet.

Under every answer, the chat shows the 3 retrieved documents by rank (1 to 3), never as a percentage: RRF scores are not probabilities.

The engine

Two open-source tools do the heavy lifting. Both run on the same machine as the API, so a classroom needs no outside service.

  • Ollama

    LLM inference

    Runs the language and embedding models locally, with no API key and no per-token fee.

    • gemma3:4b answers
    • bge-m3 embeddings
    • 1024 dimensions

  • Qdrant

    Vector database

    Stores the 15,791 verified rows and finds the best 3 for each question with hybrid search.

    • Dense + BM25
    • RRF fusion
    • Docker, port 6333

Local mode for schools

One machine, no internet needed after setup:

  • Angular frontend
  • FastAPI backend on port 8000
  • Ollama with gemma3:4b and bge-m3
  • Qdrant in Docker on port 6333

Internet is needed only once, to download the Ollama models, the Qdrant Docker image, and the BM25 model. The first start embeds all 15,791 rows before it accepts requests.

API

FastAPI endpoints: port 8000 on a local machine, the RunPod HTTPS address in the cloud
Method Path Request body Response Use
POST /ask/rag {{ askBody }} {{ ragBody }} Twins for Change: Gemma + RAG. sources are the 3 retrieved documents, best first, with no scores
POST /ask/plain {{ askBody }} {{ answerBody }} Plain Gemma with no context (A/B baseline)
GET /health/health none {{ healthBody }} (spelled as the backend returns it) The API process is up
  • The answer is Markdown written by Gemma; the chat renders it as sanitized Markdown.
  • The full answer arrives in one response. The chat reveals it word by word in the browser.
  • An answer can take a few seconds on a GPU and much longer on a laptop CPU, so the chat waits up to 5 minutes. The RunPod proxy closes requests after about 100 seconds.
  • Errors: 422 for an invalid body, 500 when Ollama or Qdrant is unavailable. The chat shows a message with a retry action.

What the backend does not do yet

The interface is ready for these features. Until the backend supports them, the chat handles them like this:

  • Token streaming. There is none: the chat reveals the full answer word by word.
  • Health of Ollama and Qdrant. The health check only shows that the API process is running.
  • Demo mode. With no backend connected, answers to the four starter questions are built from their corpus rows and labelled “Demo data”. No model runs.
